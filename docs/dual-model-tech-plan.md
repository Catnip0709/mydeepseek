# DeepSeek 双模型支持技术方案

日期：2026-09-13
状态：已确认并实施，本地 mock 回归通过；未执行真实付费 API 验证。

## 1. 目标与范围

在现有纯前端项目中恢复全局模型选择，支持：

| 界面名称 | API model | 当前实际版本 |
| --- | --- | --- |
| DeepSeek V4.1 Flash | `deepseek-flash` | DeepSeek-V4.1-Flash |
| DeepSeek V4 Pro | `deepseek-v4-pro` | DeepSeek-V4-Pro-0813 |

- 新用户默认 Flash；已有合法模型偏好继续生效。
- 全局设置覆盖普通对话、角色单聊、群聊、HTML 生成及辅助生成。
- 复用同一个 API Key 和 `https://api.deepseek.com/v1/chat/completions`，浏览器直连官方，不引入后端。
- 不增加按会话选模型、自动切换模型、图片上传或计费统计功能。
- 不调整消息、摘要、档案馆的数据结构；不因模型切换清理历史上下文。

官方依据：[模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)、[更新日志](https://api-docs.deepseek.com/zh-cn/updates/)。
截至核实日期，官方明确表示 2026-09-14 后继续提供 V4 Pro API，计费方式不变。不能再把 Pro 当作 Flash 的兼容别名。

## 3. 状态与兼容

在 `state.js` 内集中维护 `DEFAULT_MODEL`、`VALID_MODELS` 和轻量归一化函数；不新建模型管理模块或引入依赖。

| `dsSelectedModel` 的原始值 | 启动后的内存模型 | 启动时改写该存储项 |
| --- | --- | --- |
| `deepseek-flash` | Flash | 否 |
| `deepseek-v4-pro` | Pro | 否 |
| `deepseek-v4-flash` / `deepseek-v4-flash-vision-exp` | Flash | 否 |
| 缺失、空串、`deepseek-chat`、`deepseek-reasoner` 或其他非法值 | Flash | 否 |

已有用户之前保存的 Pro 偏好会恢复为真正的 Pro，费用也按 Pro 计算。这是尊重历史选择的预期行为，必须通过选中态和模型价格清晰呈现。

仅用户主动切换时写入 `dsSelectedModel`：

1. 校验候选值必须在白名单中，不将非法输入静默保存成默认模型。
2. 用 `canModifyPersistedData()` 拦截只读页面或聊天数据读取失败状态。
3. 若与当前值相同，不重复写入。
4. 尝试保存新值；成功后更新内存和单选态。
5. 保存失败时保留原模型、恢复单选态并提示失败，避免界面与刷新后的选择不一致。

初始化和切换均不调用 `saveTabs()`，不新增针对 `dsTabs` 的写入、删除或迁移。不修改既有页面锁、恢复区或存储保护逻辑。

## 4. 设置与模型详情

- 沿用现有设置布局，标题改为“模型选择”，使用同名原生 radio，分别展示 V4.1 Flash 和 V4 Pro。
- 初始化根据 `state.selectedModel` 回显，切换后立即呈现准确选中态。
- 复用现有样式和信息按钮；详情面板分别列出两种模型的能力、价格与核实日期，避免窄屏横向溢出。
- 两者均为 1M 上下文，支持思考及非思考模式；Flash 支持图像理解，Pro 不支持。
- 模型能力不等于项目已接入该能力：本期不增加图片输入，README 不将原生视觉理解写成本站已支持的图片功能。
- 不新增输入区快捷选择器或新页面。

价格单位为元 / 百万 token，顺序为空闲 / 高峰：

| 模型 | 缓存命中输入 | 缓存未命中输入 | 输出 |
| --- | --- | --- | --- |
| Flash | 0.02 / 0.04 | 1 / 2 | 4 / 8 |
| Pro | 0.15 / 0.30 | 4.5 / 9 | 13.5 / 27 |

高峰为北京时间周一至周五 9:00-12:00、14:00-18:00，其余为空闲时段。发布前复核官方页面，不把上述价格用作本地账单计算依据。

## 5. 请求生效规则

### 5.1 任务开始时固定模型

允许生成过程中修改全局偏好；已启动任务保持原模型，新任务使用新模型。不取消正在进行的请求，也不自动重试到另一模型。

模型快照只保存在局部变量和函数参数中，不写入消息或会话存储。对包含异步准备阶段的任务，应在首次 await 前获取模型。

任务边界：

- 一次发送或重新生成：TXT 压缩（若发生）、主回复、去 AI 味处理、角色翻译使用同一个模型。
- 一轮群聊：路由、角色回复、追问判断、Agent 工具循环及翻译使用同一个模型。
- 一次 HTML 生成：临时剧情摘要、正文生成、自动续写使用同一个模型。
- 一次档案馆整理：核心与扩展阶段使用同一个模型。
- 角色卡、指令优化、指令生成等独立操作：开始时取当前模型。
- 自动标题、记忆摘要及历史摘要迁移视为独立后台任务，在各自启动时固定模型，不追溯父级回复使用的模型。
- 已生成的摘要、附件压缩结果和 HTML 摘要缓存继续复用，不因切换模型额外生成或清空。

通过给现有 options 增加可选 `model`，或复用已有参数实现透传，不引入全局任务调度器。

### 5.2 默认模型与参数

- `callLLM()`、`callLLMJSON()`、`callLLMWithAutoContinue()`：显式传入的有效 model 优先；未传时使用当前有效全局模型；最后兜底 Flash。
- `translateText()` 接受 `options.model`，避免翻译阶段重新读取已变化的全局选择。
- `callLLMAgent()` 在入口固定 model，所有轮次使用同一个值，包括未显式传 model 的调用。
- `chat.js` 的直接 fetch 路径也使用固定模型，不为本次需求重构为通用请求封装。
- 普通对话、角色单聊沿用现有开关：开启传 `thinking.type=enabled`、`reasoning_effort=max`；关闭显式传 `thinking.type=disabled`。
- 群聊、工具调用、HTML 模式及辅助生成保留现有非思考行为，不因支持 Pro 改变功能约束。
- 两种模型共用现有 1M 上下文上限；不扩大应用自身的 max_tokens、重试次数或超时时间。

## 7. 验收与风险控制

1. 存储兼容：覆盖上表全部原始值；启动只归一化内存；Pro 不再回退 Flash。
2. 设置切换：Flash/Pro 双向切换、刷新恢复、重复点击、只读拦截、配额异常回滚。
3. 请求正确性：拦截并检查请求体，覆盖普通对话和角色单聊的两模型 × 思考开关组合。
4. 功能覆盖：两种模型分别验证群聊、工具调用、TXT 压缩、翻译、角色卡、指令优化与生成、标题、摘要、档案馆、HTML 续写。
5. 中途切换：在第一阶段挂起后切换模型，再放行；同一任务后续阶段仍使用原模型，新任务使用新模型。覆盖多会话并发。
6. 数据保护：单独操作模型开关不写 `dsTabs`、角色卡、指令、收藏或恢复区；消息、历史版本、摘要和档案内容不因切换被修改。
7. UI：桌面与移动端、日间与夜间模式检查选中态、键盘操作、价格可读性及文本溢出。
8. 缓存：检查静态和动态 import 版本一致，无运行时 `?v=7` 引用残留。
9. 先使用 mock 响应完成参数和流程验证，不需要真实 API Key；经授权后再进行最小真实 API 冒烟验证，确认两种模型可调用。mock 不代替官方服务可用性验证。

主要风险：恢复历史 Pro 选择会增加部分用户费用；多阶段任务漏传模型会混用；不一致的模块 URL 会导致状态分裂。分别通过价格展示、模型快照验收和统一资源版本控制。
